Three thoughtful additions.

01 / DISPLAY

Black monitor.
Colorful remote.

Ubuntu’s physical display goes black while desktop capture keeps its color. A separate watchdog restores saved display gamma ramps on disconnect or heartbeat timeout.

02 / AUTHENTICATION

A password.
And your phone.

Scan a QR code with Google Authenticator or another TOTP app. New connections require a password and an unused code, with ten single-use recovery codes for backup.

03 / DISCONNECT

Last viewer leaves.
Desktop locks.

Enable Ubuntu auto-lock to request a desktop lock after the final authenticated viewer disconnects. Other viewers can stay connected without triggering a lock.

All three features are optional and off by default in fresh installations. Screen blanking is experimental and depends on X11/RandR driver support. Test every physical monitor before relying on it for privacy.

Start with the Ubuntu host.

  1. Use Ubuntu on Xorg.Screen blanking needs an X11 session, Python 3, and working RandR gamma support. Install the build dependencies in the README.
  2. Build and start the app.The executable keeps the upstream Veyndesk name. Avoid running the original and modified host apps at the same time.
  3. Choose your protection.In Settings, enable screen blanking and auto-lock. For two-factor authentication, scan the QR code, verify a code, and save your recovery codes.
  4. Connect from Windows.Use the Ubuntu ID and password. With two-factor authentication enabled, use an updated viewer and a fresh authenticator or unused recovery code.

Before you connect

A few useful
answers.

Will Windows still show the full desktop in color?

Yes, on supported systems. Blanking changes Ubuntu’s physical-display gamma ramps while capture continues reading desktop pixels. The tested Windows-to-Ubuntu setup worked; other drivers and monitors should be checked individually.

Is this an official Veyndesk release?

No. Veynremote is an independently modified version based on Veyndesk. The original contributors built the remote desktop application. This project preserves upstream history and the AGPL license. Read the attribution.

What if I lose my authenticator?

Use one of the recovery codes saved at enrollment. Each works once. If the phone and all recovery codes are lost, recovery requires trusted local access to the Ubuntu host; there is no remote bypass. Read setup and recovery instructions.

Are there privacy or connection limitations?

Blanking may take about one second to start, and the backlight or cursor may remain visible. Monitor changes and color-management software can interfere. Direct WebRTC sessions use DTLS; upstream relay sessions are not end-to-end encrypted, and direct LAN WebSockets are not encrypted by default. Read the limitations.

Does auto-lock work if the app crashes?

It requests a lock when the host detects that the last authenticated viewer has left, including detected network/server disconnection. A hard process crash is not guaranteed to trigger locking. This is separate from the screen-blanking restoration watchdog.
